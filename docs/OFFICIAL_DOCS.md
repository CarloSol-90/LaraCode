# Fuentes oficiales y versiones

Las versiones reales se resuelven en composer.lock y package-lock.json, no en la última página encontrada. Antes de implementar una tarea, registrar paquete/versión resuelta, URL/sección consultada, fecha y decisión aplicada. No mezclar ejemplos de versiones mayores distintas.

| Tecnología | Versión del proyecto | Referencia oficial |
| --- | --- | --- |
| Laravel | 13 | [Fuentes de documentación 13.x](https://github.com/laravel/docs/tree/13.x) |
| Inertia | 3 | [Fuentes oficiales v3](https://github.com/inertiajs/docs/tree/main/v3) |
| Vue | 3 | [Guía TypeScript](https://vuejs.org/guide/typescript/overview) |
| Tailwind | 4 | [Guía oficial v4](https://tailwindcss.com/docs/upgrade-guide) |
| Pest | 4 | [Documentación oficial](https://pestphp.com/docs/installation) |
| MySQL | Objetivo 8, servidor no comprobado | [Manual 8.0](https://dev.mysql.com/doc/refman/8.0/en/) |

Laravel 13, Inertia v3, Vue y Tailwind contrastados con sus fuentes oficiales el 2026-10-22. Las páginas sin selector versionado pueden cambiar; guardar versión y revisión/fecha antes de usarlas como referencia normativa. Pest y MySQL se listan como puntos de entrada, no como evidencia de una consulta de implementación en esta tarea.

## Aplicación a LaraCodepedia

Cada contenido deberá asociar tecnología, versión compatible, URL/sección oficial, fecha de revisión y, cuando exista, revisión inmutable. Escribir explicaciones y ejemplos propios, atribuir la fuente y señalar contenido desactualizado. Cambiar una versión genera revisión del contenido y sus ejercicios; no sustituir silenciosamente evidencias históricas. No copiar documentación oficial completa ni construir un sincronizador en esta fase.
